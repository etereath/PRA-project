# 开发执行参考

角色：按需参考。仅在需要安排测试、接口适配或交付细节时读取对应节；不属于默认阅读集。任务范围、硬边界与权限以根级 [AGENTS.md](../AGENTS.md) 和用户当前指令为准。

## 接口与测试选择

修改函数签名、DTO、enum、返回结构或持久字段前，搜索生产调用处与测试调用处，集中列出直接影响。更新 fixture 时保持原业务断言；不能用迁就实现的预期值掩盖回归。

| 本次改动 | 开发期验证 |
|---|---|
| 文案、文档 | 显式编码回读、差异和相关链接；规则变更额外核对语义及冲突 |
| 纯函数、格式化、状态文案 | 轻量参数化用例覆盖边界；不为每个分支初始化 Workbook、Runtime 或 Queue |
| 接口或 DTO | 调用处与 fixture 同步适配，再验证直接受影响的调用链 |
| 持久化、授权、事务、并发、恢复 | 真实临时 Runtime 的必要集成，覆盖授权绑定、幂等、原子性及受影响的失败/重启路径 |

Bugfix 按“原问题复现 → 修复 → 直接回归 → 必要集成”推进。Task Type 与 Review Profile 按本次实际影响判断，父任务的评级不自动决定本轮测试范围。

## 验证证据与 CI

- 复用证据时核对源码、测试、依赖、配置和环境变化，说明覆盖范围。源码或测试改变、已有失败、独立环境价值及未解除风险，是重新选择验证范围的依据。
- 失败先查相关 job、stack 或 artifact；用定向复现定位原因。不能把一次失败改写成“未验证”，也不能靠反复运行到绿色认定问题已解决。
- 正式交付在稳定候选上完成适用完整门禁；等效 GitHub CI 已覆盖时，不为形式再跑本地全量。关键业务交接仍需相应集成证据，CI 不证明真实平台已验收。
- CI 分层需在工作流任务中落实：开发期轻检、纯文档检查、必要集成、交付完整门禁。相同环境和输入下去除被全量覆盖的重复子集；不同平台、隔离环境或恢复目的的检查保留。
- 文档规则不自动改变工作流触发条件，也不授予绕过现有 Gate 的权限。

## 文档与提交

开发中保留必要的简短记录，交付时统一更新相关入口和证据。小修、fixture、机械链接调整不默认新增独立报告；工作区内已存在且仍有效的历史证据保持原样。

仓库报告绑定已有实现/测试 commit，最终 PR Head 与 CI 链接写入 PR 说明。后续仅文档变化时说明与已验证源码的关系，不制造“文档记录自身最新 SHA”的提交链。

允许本地小步 commit，相关改动和验证完成后集中 push，遵循用户明确时机。最终回复只交代本轮结果、验证范围和实际相关的操作状态；需要标明未验证的实机或部署能力时，使用 NOT YET VALIDATED，不附加无关状态清单。
