# 商品资料与库存补充录入说明

> 状态说明（2026-08-12）：本文主体记录 13.5-7D 权威切换前的历史工作簿行为，仅用于
> 迁移盘点和回归。7D 切换完成后，Runtime DB 库存余额与不可变流水是唯一真实库存权威；
> `products.xlsx.current_stock` 只作为一次性 bootstrap 输入和历史只读快照，不再是日常
> 编辑字段。正式切换合同见
> [13.5-7 施工计划 6.1](plans/task13_5_7_web_rewrite_construction_plan.md#61-数据库真实库存)。

## 切换前定位

`/business-inputs` 的“商品资料与库存录入”是日常运营入口，用于维护商品资料并录入当天可销售库存。

当前阶段仍然遵守以下边界：

- 商品主数据继续保存回 `products.xlsx`。
- Excel 仍是业务输入来源。
- SQLite 仍只保存运行态任务、复核、通知、执行日志等事实数据。
- 不新增 SQLite schema。
- 不迁移 Excel 主数据。
- 不删除旧 `/tables` 表格编辑入口。

这些边界只描述切换前历史实现，不能作为 7D 后保留 Excel 库存写入口或旧 Web 兼容页的
依据。

## 13.5-7D 切换后的职责

- `product_inventory_input.py` 拆分商品资料/成本/是否销售与库存调整；
- 新花入库、盘点、损耗、人工修正和对账只创建 DB inventory transaction；
- 新 SKU 先保存商品资料并获得零 DB 余额，再以独立幂等“新花入库”事务增加库存；
- TaskGeneration、ListingDecision、`SET_ONLINE` 上限和库存预警只读统一 Inventory
  Provider/Application Service；
- 禁止同时写 `products.xlsx.current_stock` 与 DB 库存；
- 切换后的代码回滚不得把过期工作簿库存恢复成权威。

当前实现按权威状态执行：`PRE_CUTOVER` 时保留历史工作簿行为，便于在正式维护窗口前继续
运营；`DB_AUTHORITY` 后旧“补充库存”入口整体拒绝，商品资料编辑即使继续保存名称、等级、
规格、成本和销售开关，也不能改变 `current_stock`。新增 SKU 必须先以历史字段 0 保存商品
资料，再通过 `create_authoritative_product_with_inbound()` 回读证明 SKU 已存在，调用
`InventoryApplicationService.initialize_sku()` 建立可重放的零余额和 `SKU_INITIALIZATION`
流水，最后通过独立人工“新花入库”调整增加库存。任意字符串不能初始化孤儿余额；缺少任一步时统一
Inventory Provider 失败并要求维护，绝不回退工作簿库存。

切换前，旧 `/tables` 继续作为高级兼容入口，适合批量维护、排障或直接编辑原始表格；
7D 新 Web 切换后该兼容入口按施工计划删除，不能继续编辑库存。

## 页面录入方式

当前页面采用“选择已有品种 + 新增品种弹窗”的录入方式：

- 主表单中的“品种”是选择框，优先选择 `products.xlsx` 中已有品种。
- 如果列表中没有目标品种，点击“新增品种”，在弹窗中填写新品种名称和品种代码。
- 主表单不常驻展示“品种代码”输入框，品种代码只在新增品种时填写，用于 SKU 生成。
- “本次入库数量”是页面上的库存补充字段，保存后累加到商品的“当前库存”。
- 基础成本当前默认值为 `6`，用于低价风险判断，不直接展示给销售平台。
- 输入框、选择框和提交按钮应保持统一高度与对齐，避免运营录入时产生误读。

## 库存录入原则

库存录入是“补充公共库存”，不是简单“新增商品”。

保存“补充库存”时，系统先按以下同类型条件查找现有商品：

- 品种 `product_name`
- 等级 `grade`
- 枝长/规格 `stem_length`
- 单位 `unit`

匹配前会做标准化：

- `product_name` 去除前后空格。
- `grade` 转为大写字符串，等级 `"0"` 保持字符串处理。
- `stem_length` 中 `跟随等级 / follow_grade / FG` 会先按等级解析为实际枝长，再参与比较。
- `unit` 统一为 `扎 / 半扎 / 枝`。

平台不参与库存匹配，成本不参与库存匹配，是否允许销售不参与库存匹配，SKU 也不是用户输入的匹配条件。

## 保存行为

如果找到唯一同类型商品：

- 不新增商品记录。
- 保留原 `internal_sku`。
- 当前库存 = 原当前库存 + 本次入库数量。
- 同步更新 `base_cost` 与 `sale_enabled` 为本次表单值。
- 页面提示：“同类型商品已存在，本次保存会补充库存，并将基础成本、是否允许销售更新为本次填写值。”

如果没有找到同类型商品：

- 新增一条商品资料。
- 自动生成 `internal_sku`。
- 当前库存 = 本次入库数量。
- 写入基础成本、是否允许销售等字段。

如果找到多条同类型商品：

- 拒绝保存。
- 提示用户先检查商品主表。
- 不静默选择其中一条，不继续制造重复记录。

## SKU 规则

SKU 基于商品类型生成，不包含平台。

当页面选择“跟随等级”时，系统按以下规则解析为实际枝长：

| 等级 | 枝长 |
| --- | --- |
| `A` | `65` |
| `B` | `60` |
| `C` | `55` |
| `D` | `50` |
| `E` | `45` |
| `0` | `0` |

保存到 `products.xlsx` 时写入解析后的实际枝长。历史数据中如果仍存在 `跟随等级 / follow_grade / FG`，系统读取和匹配时也会按当前等级解析，避免旧数据失配。

规则为：

```text
品种代码-等级-枝长代码-单位代码
```

示例：

- `艾莎 + B + 跟随等级 + 扎 -> AISHA-B-60-Z`
- `卡布奇诺 + A + 70 + 扎 -> CAPPUCCINO-A-70-Z`

品种代码优先来自维护映射表。未知品种如果没有映射，第一版要求运营人员通过“新增品种”弹窗填写品种代码，否则拒绝生成 SKU。

约束：

- 不使用随机值生成 SKU。
- 不把平台写入 SKU。
- 不在主表单长期暴露品种代码输入框；品种代码属于新增品种时的 SKU 生成辅助信息。
- 如果 SKU 与已有不同类型商品冲突，系统使用稳定后缀避免覆盖，或提示检查商品主表。
- 编辑已有商品时默认不自动改变 SKU。

## 平台与库存边界

初始库存录入默认不绑定平台。

原因：

- 当前录入的是基地可销售公共库存。
- 商品在特定平台售出后，后续再通过销售记录或转化记录形成平台标签。
- 平台标签用于统计分析，不用于本阶段库存归属。
- 不要把公共库存提前拆成平台库存。
- 不要因为某个平台常用，就把新库存默认归属到该平台。

本阶段库存录入表单不显示平台字段。

当前已准备 `data/samples/platform_mappings.xlsx`，用于保存销售平台选项和后续平台商品映射占位。

首批平台包括：

- 寻梦
- 花伍
- 珍情
- 花易宝
- 蚂蚁
- 花宝宝

库存录入页提供“新增平台”入口，但该入口只维护平台选项，不会把本次入库库存绑定到某个平台。价格规则中的平台选项会优先读取这张平台映射表。

## 字段校验

录入库存表单校验：

- 品种不能为空。
- 等级不能为空，`"0"` 是合法等级。
- 枝长/规格不能为空，`跟随等级` 是合法值。
- 单位不能为空。
- 基础成本必须是数字且 `>= 0`。
- 本次入库数量必须是整数且 `> 0`。
- 是否允许销售必须是“是/否”。

编辑商品表单校验：

- 可编辑品种、等级、枝长/规格、单位、基础成本、当前库存、是否允许销售。
- 当前库存不得小于 `0`。
- 编辑后的 `product_name + grade + stem_length + unit` 不得与其他商品重复。
- `internal_sku` 只读展示，默认不允许编辑。
