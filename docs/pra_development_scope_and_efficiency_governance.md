# PRA 开发范围与效率治理规范

角色：Developer Governance / WHY & WHEN。本文只定义阅读与修改范围、扩大范围的条件、不处理的问题、完整 Gate 的适用时机和停止条件。操作步骤统一放在[开发执行参考](development_workflow.md)，硬边界与权限以根级 [AGENTS.md](../AGENTS.md) 和用户当前指令为准。

项目进度由[当前状态](project_current_status.md)维护；[索引](index.md)只提供文档导航，不保存进度。

## 1. 读多大范围，以及为什么

阅读投入以能改变当前任务判断的证据为限。起点是根级 AGENTS、当前状态、用户指定对象、相关版本以及直接受影响的实现；同一任务后续复用仍有效的基线，只读增量。

- 产品目标或业务定义不清时，读取对应业务主文档。
- 修改涉及公共合同、持久状态或组件责任时，覆盖其直接依赖链。
- 已有证据覆盖相同源码、测试、依赖、配置和等效环境时，允许复用；影响结论的变化才要求补充证据。
- 仓库规模、父任务规模和历史材料数量，不构成扩大阅读范围的理由。
- 开发任务不自动切换为全项目审核。明确要求审核时，范围仍以用户指定对象为准。
- 接受审核任务不自动启用归档规范；`.archive/` 材料须由用户在当前请求中明确点名，才可读取或使用，不通过开发入口间接导入。

## 2. 何时扩范围

只有实际影响或新证据构成直接依赖时，才扩大到相应范围。

| 触发条件 | 必要关注范围 |
|---|---|
| 真实平台写或其授权行为改变 | 主体与范围、写前比较、写后回读、幂等和 UNKNOWN 处理 |
| Schema、持久状态、lock 或 authority 改变 | 当前 owner、原子事务、重启恢复与权威唯一性 |
| 公共接口、DTO、enum 或持久字段改变 | 直接生产与测试调用链、数据合同 |
| 跨组件职责或恢复路径改变 | 受影响的完整业务交接与终态责任 |
| 同根因直接影响入口、修改引入的回归、妨碍修复的结构缺口 | 完成当前修复所必需的直接整改 |
| 新证据明确破坏硬安全边界 | 相应安全处置与必要验证，不扩大真实操作权限 |

CI 失败仅在阻碍当前目标、由当前修改直接引入，或属于用户明确授权的 CI 整改时，进入本轮处理范围。普通文档评阅不因存在无关失败而转向 CI 排查。

新增表、Service、daemon、Queue、状态机或兼容层，须有具体业务事故与既有能力不足的依据。现有结构能承担责任时优先复用；理论上的未来用途不构成扩建理由。边界阻碍目标时显式说明冲突，不能通过旁路扩大授权。

## 3. 什么问题不处理

- 独立于当前目标的历史文档错误、其他模块 warning、无关测试失败、旧架构债务和其他平台缺陷，不自动加入本轮任务或完成条件。
- 既定整改清单之外的可讨论问题，不自动成为新 blocker；必要时简短记录为后续项。
- 已由用户或有效状态记录关闭的阶段与问题，不反复重开；只有新证据直接冲突时才重新核验。
- 开发者不自行重复审核端对整个阶段的裁决，也不将 Reviewer checklist 变成普通开发前置条件。
- 小修不默认新增长报告；新业务能力、迁移、复杂恢复、实机验收或重要故障需要长期证据时，才建立专门报告。

## 4. 何时需要完整 Gate

稳定候选需要判断与改动风险相匹配的适用 Gate；是否主动运行完整 Gate 仍受根级 [AGENTS.md](../AGENTS.md) 的资源授权约束。用户当前请求已明确要求相应完整验证时复用该授权，不重复询问；开发中的局部反馈采用与影响匹配的定向验证。资源预算不得降低授权、持久化、事务、并发和恢复所需的真实临时 Runtime 集成证据；所需验证超过预算时先申请扩大范围，未获授权不得将定向结果写成完整 Gate 已通过。

- 源码、测试、依赖、配置或环境发生影响结论的变化，或存在尚未解除的相关风险时，重新判断适用的完整 Gate。
- 相同输入与等效环境已有完整 CI 证据时，不为形式重复本地全量。
- 仅 Markdown 变化不自动要求重新验证源码逻辑，也不自动授权调整 CI 工作流。
- 仓库自动触发的 Gate 仍按其实际结果记录，不能绕过；CI 通过不能替代受控实机、部署或长期运行证据。
- 相关 CI 失败须有原因和验证依据才可收口；已证实并恢复的外部环境故障可以在同版本重跑，不要求制造仓库改动，但 Agent 主动重跑前必须按根级 `AGENTS.md` 重新取得授权。执行步骤见开发执行参考。

## 5. 什么时候停止

用户指定目标完成、原问题与直接回归验证通过、必要集成及本次适用交付门禁满足后，应结束本轮工作，不继续寻找无关问题。

- 已知且直接阻碍当前交付的失败仍属于本轮任务，不能仅因“状态已明确”宣告完成。
- 用户明确限制本轮只做诊断、一次 CI 或指定步骤时，达到该范围即停止，并如实保留未完成项；不把失败写成通过。
- 等待人工授权、现场验收或其他外部依赖时，记录实际负责者、下一触发与所需证据，不能靠扩大代码或审核范围替代。
- 文件编码、隔离测试、CI、实机与部署是不同证据；阶段状态只依据相应裁决和证据更新。
- 本轮交付完成后，新的独立审核或开发目标需要新的任务范围。
