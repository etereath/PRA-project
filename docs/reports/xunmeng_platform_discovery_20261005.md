# 寻梦供应商：平台接口探索

日期：2026-10-05（Asia/Shanghai）。角色：旁路现场探索；与[锦成探索](jincheng_platform_discovery_20261005.md)同属 Draft [PR #68](https://github.com/etereath/PRA-project/pull/68)。源码复用判断绑定 `main@aaa93497ea2862fc80d303be2aeafc65227d943b`。

## 范围与结论

用户打开“寻梦供应商”后，使用现有登录态、Windows 界面和 accessibility，完成下表 X01～X24 的页面导航、查询和表单查看。设置页文本显示版本 **v2.2.46**。本轮只读探索完成，尚未实现寻梦 Reader / Adapter / Executor，也没有正式采集包、Runtime 导入或真实写验收。

**接入主线为影刀 / ShadowBot 界面自动化。** 用户已明确不应预设此类平台有官方开放 API；HTTP 资料仅在后续实际获得时作为可选补充，不是本任务完成或 UI 接入的前置条件。微信 `page-frame.html` 是容器地址，不是业务接口。本轮未抓取、重放或验证业务 HTTP 请求，也不据此断言平台完全没有接口。

寻梦商品、订单和部分统计页出现明确“没有更多了”，可用于后续完成证据；但日期是场次口径，价格、结算、代卖与售后单位不能混用。读取必须排除初始零值、临时空态以及返回页面保留的旧滚动位置。

“观察”仅代表本次页面实际出现；“建议”是适配推断；“未验证”不得改写为生产能力。下表是导航证据索引，不是 API endpoint。原始页面只在会话内检查，Git 不保存商户身份、客户资料、实际单号、经营金额、凭据或原始截图；脱敏记录不能代替 hash-bound 正式事实及验收包。

## 商品字段和写入边界

### 身份与范围

现有 [PLATFORM_OPTIONS](../../app/services/product_inventory_input.py) 已有 `寻梦`。窗口名 `寻梦供应商` 属于 UI 名称；后续接入应核对现有平台别名映射，不直接扩出第二个公共平台键。继续使用 `platform_name`、`platform_product_identity`、`internal_sku` 三层身份。

列表既有普通玫瑰名称，也有带 `o级单头玫瑰…` 前缀的名称，等级为字母 **O**，不能解析成数字0。目录也分普通单头玫瑰与 O级小花。名称前缀不是可以无条件删除的装饰；同名同级是否存在不同规格、目录项与已上架商品的关联尚需验证。读取候选歧义时应失败，不能猜 SKU 或借用锦成身份。

商品列表的“已售”不是当日销量，统计时间跨度尚未证实；库存是页面当前字段，不代表农场实物总库存。每扎支数因商品而异，不硬编码20。价格排名和最低售价是参考字段，不是本商户供货价。

### 一次动作可能涉及多个字段

- 库存快捷面板带退货转代卖设置；编辑页还包含媒体、评级、限购与补货自动上架。后续必须确认提交范围，以及改价是否同时写回旧数量或经营设置。
- “补货自动上架”的页面说明把增加库存与售完自动下架后的重新上架联系起来。**补库存可能改变在线状态**是明确需要验证的风险；本轮未切换或触发该行为，不能宣布已验证自动上架。
- 供货价有独立弹窗和一键出价，确认的远端副作用边界未知。不得为了找最后一个确认按钮而无授权点击；写流程应先在适当环境验证边界。
- 已下架可有正库存，也可叠加已售罄；视频推广中可与已下架共存。商品过期和视频过期必须分别识别。
- 未修改表单时，评级页返回后的媒体展示与之前不同，而商品列表仍有视频推广标识。只能记录 UI 展示/加载差异；没有提交证据，不能断言视频已被删除，也不能盲目提交整表修复它。

复用既有持久授权与 `写前读取 → expected old 比较 → 一次执行 → 独立写后读取`。写入范围必须包括实际可能改变的经营状态；结果不确定交给现有 UNKNOWN / 唯一 RECONCILE，不用重复点击确认碰结果。本轮没有验证数值范围、幂等、并发、写后回读或平台自身的自动状态转换。

## 订单、场次、结算和售后

历史订单查询选择2026-10-03时，结果包含2026-10-02晚间及10-03的实际下单时间；这些行的扎数/合计加总与对应送货场次的汇总一致。本样本支持“查询日期对应场次”的解释，**不支持直接套用自然日过滤或其他平台营业日配置**。18:00停止接单是页面事实，精确边界、边界秒、跨日/取消规则仍未验证。

采集应保留选择范围和每行实际下单时间，不按自然日去掉前晚订单；不能假定列表按时间降序。订单号在界面上可读，是比仅名称/时间更好的去重线索，但单号的跨类型唯一性、子行身份、取消/售后更新关系尚未验证。接入应先复用现有 importer 去重合同，不能因为页面有单号就默认该单只会出现一行。

履约状态、结算状态、送货完成是不同维度。普通订单“全部状态”候选还包含待付款、已取消，不能把全部可见金额一概当有效成交；本次没有对应非空样本支持精确规则。`合计`、交易合计、供货价、净结算和卖家赔付分别记录，不用净结算覆盖成交额。

售后赔付单位为枝，交易单位为扎，换算需要当时商品规格；卖家承担与平台承担也不同。售后申请/处理时间不等于下单时间。退货转代卖是独立供货及定级/结算视图，顶部统计月份不能未经验证当作下方历史列表的筛选月份。这些观察不授权修改库存 ledger 或扩展新的财务系统。

## UI 采集可行性和完成证据

- 界面主要字段可通过 accessibility 读取，长图、视频、开关选中状态仍需要视觉核验。索引随导航/重载变化，不能固化为选择器。
- 列表逐步补载，较大滚动量也只推进有限距离；本次商品从10行补到13行后才出现终点。分页读取应记录行去重、补载和终点，不用一次截图的行数当完整结果。
- 当前和历史普通订单均实际看到了“没有更多了”。这解决了“有无候选终点”的勘察问题，并未完成正式读取器的完整性验收。重新导航到相同订单页还可能先显示“加载更多”，需要重新等待/确认。
- 空态和零值有明确的加载误读风险。首页摘要、编辑数量、筛选结果均出现过占位值；要结合当前范围、加载完成与稳定读取，不设固定短等待后就判零。
- 页面返回保留历史日期、滚动位置；恢复查询时要确认可见选择值。订单和商品会在经营中变化，终点本身不提供跨页原子性保证。

### 与锦成的直接差异

| 项目 | 锦成已观察 | 寻梦已观察 | 接入含义 |
|---|---|---|---|
| 商品列表完成 | 标题总数与21行相符，明确到底 | 无标题总数，首批10行补到13行，明确无更多 | 分平台保留完成证据，不能抄固定页大小/总数字段 |
| 订单入口 | 单品成交详情，无明确末尾标志 | 独立订单页，单号及明确末尾标志 | 可复用读取职责，不能共用页面解析或伪造锦成终点 |
| 日期 | 送货日和下单自然日不同 | 历史场次也含前晚下单 | 分平台验证场次算法，不直接复用截单时刻 |
| 库存面板 | 数量与加减确认 | 数字键盘，同时有代卖设置 | 提交范围需分别验证 |
| 新增商品 | 当前商品库不可用 | 可查看新增表单和已开通目录 | 平台权限限制不能相互外推 |
| 结算 | 收益权限不可用 | 账单汇总可读，待结算详情为空 | 可读性和金额语义分别判断 |

## 复用方案与下一步交接

当前缺口是寻梦专属 Reader、字段映射和 UI 执行边界，现有 [ProductObservation](../../app/services/product_observation.py)、[OrderObservation](../../app/services/order_observation.py)、[商品身份](../../app/platform_product_identity.py)、[Reader/Adapter 分工](../../app/adapters/mayi_huatuan_order.py)以及 [ShadowBot Executor](../../app/services/shadowbot_executor.py)可承担既有职责。没有需要新增 Queue、Service、状态机、账号绑定或 page identity proof 的具体事故证据，本轮也没有新增这些机制。

| 下一工作 | 负责者及触发 | 完成证据 | 失败后的处理 |
|---|---|---|---|
| 商品只读适配 | 后续寻梦接入开发任务开始后，由该任务开发者负责 | 脱敏/合成样本覆盖补载终点、临时空态、O级目录身份、价格/数量/状态分离；通过既有接收链得到可核对的事实 | 歧义/范围不完整保留失败或部分结果，不导入完整零事实 |
| 订单只读适配 | 同一接入任务，先明确场次和有效成交口径 | 历史非空、跨日、状态和重复子行样本；全页遍历/终点、聚合对账、重复导入及正式 importer 结果 | 日期/状态口径不明则返回开发者补证；不删前晚订单或以汇总替代逐笔 |
| 写入边界验证 | 负责人安排具体 SKU、动作、expected old、target、有效期和环境后 | 库存/价格弹窗与整表提交边界，自动上架/代卖设置联动；沿既有持久授权和独立回读闭环 | 提交前无法证明目标或范围则失败；提交后不确定进入既有恢复责任，不再次猜测写 |
