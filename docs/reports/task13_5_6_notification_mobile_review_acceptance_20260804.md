## 3. 手机复核链接 404 与整改

首次 S4 通知使用验收期临时 cpolar 域名。发送当时公网页面为 `HTTP 200`，但临时隧道进程
在次日已退出；用户随后点击旧消息时得到 404，同时旧 Review Token 也已超过有效期。

整改过程：

1. 保持隔离 Web 和 Runtime DB 不变，确认本机复核页仍可正常返回；
2. 使用账号已有的固定 cpolar 子域名重新暴露隔离 Web；
3. 公网 `/health` 返回 `HTTP 200 / ok` 后，作废旧 Token；
4. 对同一极端低价经营场景重新签发 30 分钟有效的 Review/Token/Outbox；
5. 在不输出完整 URL 或 raw token 的前提下，验证公网复核页为 `HTTP 200` 且三个动作存在；
6. 补发最新 S4 通知，飞书再次返回 `SENT / ACKNOWLEDGED / HTTP 200`；
7. 用户使用最新消息完成手机端验收。

此问题不是 Mobile Review 路由、Token hash 或飞书发送失败，而是验收入口错误使用了短生命周期
公网域名。后续不得把随机临时域名写入会发送给运营人员的 `MOBILE_REVIEW_BASE_URL`。

## 4. 固定运行要求

- `MOBILE_REVIEW_BASE_URL` 必须使用受运维管理的稳定 HTTPS 地址；随机临时隧道只允许本地
  探索，不允许进入真实通知。
- 受控真实通知验收前先从公网入口检查 `/health`，再生成 Review；本地 200 不能替代公网可达。
- 公网地址变化或 Token 到期后，不修改或复用旧链接；应作废旧 Review/Token，重新生成新的
  Review/Token/Outbox，并明确让运营人员使用最新消息。
- 通知业务事务仍只写 Outbox，不在事务内探测公网或发送网络请求；公网健康由部署/运维门禁
  负责，不能破坏现有 Outbox 事务边界。
- 仓库、报告、通知日志和控制台均不得保存 raw token、完整 `token=` URL、Webhook 或收件人
  身份；验收临时令牌文件已删除。
