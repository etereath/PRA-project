### 3.1 影刀能力依据

本地影刀文档显示：

- 影刀常规指令包含“网页自动化、桌面软件自动化、鼠标键盘、Excel、数据处理”等能力，见 `doc\影刀PRA文档\快速入门.md` 第 149 行。
- 软件操作自动化的三要素是“获取软件窗口对象、捕获软件元素、选择合适的指令”，见 `doc\影刀PRA文档\快速入门.md` 第 575 行。
- 软件元素捕获支持标准模式和深度模式，见 `doc\影刀PRA文档\快速入门.md` 第 591-595 行。
- 元素无法捕获时，可使用鼠标键盘与图像自动化，见 `doc\影刀PRA文档\快速入门.md` 第 619-650 行。
- 功能文档进一步提到 Windows 软件可使用深度模式捕获；遇到企业微信、旺店通等常规模式无法捕获的情况，可使用 CV 智能模式捕获，但图像识别容易受分辨率影响，见 `doc\影刀PRA文档\功能文档.md` 第 1504-1506 行。
- AI 辅助定位可在精准定位失败时作为兜底，但主要面向 Web 元素，且有额度限制，见 `doc\影刀PRA文档\功能文档.md` 第 1847-1952 行。

这些资料说明：桌面端微信小程序可优先尝试“软件窗口对象 + 深度模式元素捕获”，若控件不可见，再退到“CV 图像定位 + 坐标/键盘动作”。

### 3.2 影刀调度与回调依据

- 支持通过 API 启动任务，见 `doc\影刀PRA文档\开放API.md` “启动任务API”。

```text
  -> 回写执行日志/截图/结果
  -> PRA 根据结果更新任务状态与复核记录
```

## 6. 推荐原型流程

建议在影刀客户端内建立一个最小可验证流程，命名为：

```text
微信小程序_商品改价_原型
```

主流程参数建议：

| 中文字段名 | 程序 ID | 类型 | 说明 |
| --- | --- | --- | --- |
| 平台名称 | `platform_name` | 字符串 | 例如“蚂蚁花团供应商” |
| 商品关键词 | `product_keyword` | 字符串 | 用于搜索或筛选商品 |
| 商品编码 | `platform_sku` | 字符串 | 若平台支持，优先用编码定位 |
| 加价金额 | `price_delta` | 浮点数 | 本轮为 `0.5` |
| 是否提交 | `should_submit` | 布尔 | 首轮建议 `false`，只停在确认页 |
| 运行批次号 | `run_batch_id` | 字符串 | 用于幂等与日志关联 |

最小流程：

1. 获取微信小程序窗口对象，窗口标题匹配“蚂蚁花团供应商”。
2. 等待首页或商品管理入口出现。
3. 点击商品/商品管理入口。
4. 搜索 `product_keyword` 或 `platform_sku`。
5. 进入第一个明确匹配商品的编辑页。
6. 读取当前价格文本，转换为数字。
7. 计算 `new_price = current_price + price_delta`。
8. 填入新价格。
9. 截图并打印日志：商品、旧价、新价、页面状态。
10. 如果 `should_submit=false`，停在确认前并结束为“待人工确认”。
11. 如果 `should_submit=true`，点击保存/提交，并截图验证保存后的价格。

首轮建议只做到第 10 步，确认元素稳定、价格字段无歧义、保存按钮位置和业务含义明确后，再打开第 11 步。

## 7. 技术可行性判断

### 7.1 可行点

- 目标应用进程与窗口已存在，具备真实调试入口。
- 影刀支持桌面软件自动化，能获取窗口对象、捕获软件元素。
- 对 WeChatAppEx 这类桌面壳应用，可用深度模式和 CV 图像模式组合。
- PRA 当前已有运行态任务、执行日志、人工复核、Mock 平台验证，适合扩展真实执行器边界。
- 影刀开放 API 可用于后续由 PRA 触发任务、查询状态和接收回调。

### 7.2 主要风险

| 风险 | 影响 | 缓解方式 |
| --- | --- | --- |
| 微信小程序控件树不稳定 | 元素捕获失败或误点 | 优先使用深度模式；失败时用图像定位和锚点；固定窗口大小 |
| 小程序页面结构更新 | 流程运行失败 | 元素命名版本化，建立每日冒烟用例 |
| 商品列表相似项多 | 误改商品 | 必须用 SKU/商品编码二次校验，不只按名称 |
| 价格字段多 | 改错价格类型 | 捕获字段时使用中文锚点，如“销售价”“平台价” |
| 保存动作真实生效 | 误改真实平台 | 首轮 `should_submit=false`，人工确认后再开真实提交 |
| 网络/登录态失效 | 流程中断 | 开始前检查登录态和首页关键元素 |
| 执行结果不可审计 | 无法追责 | 每次执行保存截图、旧价、新价、任务 ID、运行日志 |

## 8. 与 PRA 的接入边界建议

建议新增真实 RPA 执行器，而不是改造 Mock 执行器：

```text
RuntimeTaskService
  -> RealRpaExecutor / ShadowBotExecutor
  -> ShadowBot API 或影刀任务参数
  -> WeChatAppEx
  -> execution_logs
```

建议规则：

- `pricing` 和 `business_rule_evaluation` 只生成建议，不直接操作真实平台。
- 人工复核通过后，运行态任务进入 `pending_rpa` 或类似状态。
- 真实 RPA 执行器只消费已批准任务。
- 执行器必须写入旧值、新值、截图路径、影刀 job/task id、结果状态。
- 平台库存不得反向覆盖 PRA 公共库存。
- 首版只允许已审批任务、单商品、小批量执行，并要求旧价校验和提交后对账。

## 9. 验收建议

进入真实提交前，建议按以下顺序验收：

1. 影刀内人工捕获并调通“只查看商品”的流程。
2. 调通“读取当前价格并截图”的流程。
3. 调通“填入新价格但不保存”的流程。
4. 在测试商品或低风险商品上调通“保存加价 0.5 元”。
5. 从 PRA 生成任务并把参数传给影刀。
6. 影刀执行后把结果回写 PRA `execution_logs`。
7. 用人工复核页确认任务状态、旧价、新价、截图证据一致。

## 10. 最终判断

通过影刀 PRA 控制桌面端微信小程序进行商品改价，技术上可进入原型验证阶段；但必须把真实提交动作放在人工复核和执行审计之后。

本次环境已证明目标程序存在、影刀能力匹配、PRA 有可扩展的运行态边界；进一步探索还证明 `WeChatAppEx` 可由桌面自动化读取、截图、点击、编辑并提交真实价格修改。本次已完成 `C级艾莎` 从 `¥8.50` 到 `¥9.00` 的加价验证，并在列表中复核成功。

建议下一步由人工在影刀客户端复刻该流程，优先使用深度模式捕获；对 WebView 难捕获区域使用 CV 智能模式或图像库兜底。PRA 侧应通过人工复核后的任务参数触发影刀流程，并将旧价、新价、商品、截图和执行状态回写 `execution_logs`。
