# 锦成入驻商家：平台接口探索

日期：2026-10-05（Asia/Shanghai）。角色：旁路探索记录，不是生产接入或实机写验收。

## 目标与范围

主任务等待实机期间，探索用户已打开的锦成供应商小程序，识别可供 PRA 复用的商品、订单、履约、统计与结算读取入口，以及真实写入前必须明确的边界。独立分支基于 `main@aaa93497ea2862fc80d303be2aeafc65227d943b`，不改变主任务 worktree、Runtime、Queue 或 Worker。

仅导航、查询和查看表单；不提交商品修改、上下架、库存、订单、结算、提现、申请或消息。本记录不包含商户身份、真实订单标识、经营流水、凭据或原始截图。

## 本轮结论与证据等级

**已完成一轮广泛的只读现场探索；尚未实现锦成 Adapter，也没有验证真实写链路。** 商品列表具有可验证的加载终点；成交明细有可用字段，但日期语义、完整性和金额口径仍需接入前处理。不能直接复制蚂蚁花团页面解析和营业日配置。

用户随后明确不应预设此类平台提供官方开放 API，因此接入主线为**影刀 / ShadowBot 界面自动化**；HTTP 资料仅是后续可选补充，不作为探索完成或 UI 接入的前置条件。同一旁路已继续探索[寻梦供应商](xunmeng_platform_discovery_20261005.md)，两个平台分别保留 Reader 和语义判断。

- 用户称“锦城”，实际窗口/小程序名为 **锦成入驻商家**，工作台显示版本 **4.4.5**。
- 探索使用现有登录态、Windows UI 和 accessibility；下表 E01～E22 是本轮实际访问/操作的证据索引，不是 HTTP endpoint 编号。
- “观察”表示页面或文本确实出现；“建议”表示由观察推导的适配方案；“未验证”表示不能据此声明生产能力。空态仅针对所选范围，不外推为整个业务无数据。
- 原始页面在会话中检查，Git 仅存脱敏结构和结论。未保存可独立重放的原始采集包，因此本报告不作为正式 ProductObservation / OrderObservation 输入或 hash-bound 实机验收证据。

## 商品读取与写入语义

### 身份与单位

商品卡片包含花材名称、等级、成熟度、每扎支数、枝长/长度区间；“支/扎”和“枝/扎”两种文字均出现，长度有 `≥`、区间和 `CM` 等表示。未读到稳定商品 ID。商品可定位性暂由页面显示组合支持，**同名同级是否可能存在多个规格仍未证实**。

建议继续使用 `platform_name + platform_product_identity → internal_sku`。稳定 ID 若后续可获得则优先使用；没有 ID 时须核验候选商品唯一性及规格，不沿用其他平台同名同级的 SKU 推断。歧义应在读取/写入前失败，不增加 account/session/page 认证系统。平台自身的子账号标识和收益权限不构成 PRA 新增多账号模型的理由。

### 价格

列表同时存在卡片主价格、平台补贴（元/扎）、平台售卖价、结算价、竞争价格以及价格排名。accessibility 可把主价格拆成 `¥`、整数、小数三个文本节点；按全页第一个数字或第一个人民币符号提取会误取。

本轮对有补贴商品进入编辑，确认其**供货价与该商品列表结算价相等，平台售卖价另列**；这只是所查看样本的关系，不能外推所有渠道的统一结算公式。未来 UPDATE_PRICE 首先明确管理者要改的字段是供货价；平台售卖价、补贴、佣金、成交合计和最终净结算不得互相替代。

### 上下架、售罄与数量

- “已售罄”与“已下架”可同时出现；各标签不是互斥枚举。
- 本轮还实际观察到在售商品数量变为零后标为售罄，但仍保留“下架”按钮；零库存不等价于显式下架。
- “已下架”商品可以有正库存。不能以数量正负单独推断 online/offline，也不能以“出售中”集合覆盖全部平台已上架商品。
- 平台库存先视为可售数量候选，不能直接当 PRA 实物库存；自动售罄后的可售/展示语义仍需独立定义。
- 库存快捷弹窗有明确“确定”，编辑商品也有库存字段。后续改价若整表提交，必须证明不会把过时库存、媒体、退货策略等无关字段写回；本轮没有请求体证据。

### 编辑及隐藏门禁

实际编辑页观察到必填标识、最多 8 张图片、最多 1 个视频、“退货转代卖”的说明。该说明表示不合格退货可能由质检重新定级定价后转代卖，不能将其当普通价格选项切换。

列表/编辑的 accessibility 还包含价格偏离市场均价、禁售、图片未更新、超过30天未更新、转代卖会清库存并下架等提示模板。部分模板含 `undefined` 或上一商品名称，截图中并未呈现对应弹窗。这些只能作为**待验证门禁线索**，不能宣称本轮触发过，也不能自动点击其中的确认文本。

## 成交、营业日与履约

### 读取路径与字段映射候选

可靠入口候选为“销售统计 → 选择日期/渠道 → 各花材等级 → 详情”。底部“自营订单”在本登录态是 NFC 入位，不能按名称直接选为 ORDER_SCAN。

| UI 字段 | 既有 OrderObservation 候选 | 约束 |
|---|---|---|
| 下单时间 | `order_created_at` | 保留完整时刻，时区配置需按锦成核验；不截断成归属日 |
| 花材、等级 | `platform_product_name`、`grade` | 规格歧义必须处理，C+/D+/O 不擅自折成 C/D/0 |
| 行内数量（扎） | `order_qty` | 不是每扎支数、买家数或订单数 |
| 行合计（元） | `order_transaction_amount` 候选 | 先核实补贴/优惠/售后含义；不把结算净额或当前供货价乘数量当原成交额 |
| 统计页所选日期 | `requested_platform_trade_date` / 来源日期候选 | 目前 UI 表达送货日期；需确认与 PRA 平台交易日的对应关系 |
| 本次采集时刻 | `observed_at` | 由采集器记录，不能用下单时刻或历史日期冒充 |

上述是适配候选，不是已经创建的 DTO、配置或 Runtime mapping。

### 日期和完整性风险

1. 当日送货的成交详情实际包含前一晚下单记录，证明下单自然日不能直接作为这组订单的归属日。
2. 历史日期查询有效，但单品详情标题仍写“今日成交明细”；上层“今日送货/明日送货”快捷计数也不随历史日期同步为该日计数。应绑定所选日期、渠道与行内容，不能抓标题作为日期真值。
3. 明日按钮明确切到次日，出现零汇总和最终空态。需等加载完成后同时核验日期、渠道和空态，不能只见零行就接受。
4. 历史单品详情滚到底后，已读取行数/数量/合计与页头摘要可相互核对，但未见明确终止标志；也未验证大量订单分页、同秒相同订单重复、换货及所有渠道覆盖。**成交完整扫描未通过证明**，不能直接标记 ACCEPTED。
5. 成交行未见稳定订单 ID；货位号可能为“待分配”，客户名为简写，二者都不应当作订单唯一键。既有 fingerprint + occurrence 能力应优先评估，不能新增一套以客户资料为核心的身份系统。
6. 本轮商品销量、可售数量、排行和工作台汇总自然变化；来源未冻结，不同时间页面汇总不能强求完全相等，也不能把后读事实覆盖旧观察。

### 异常与扫码

降级详情提供原商品等级/单价、降级数量、降级后等级/单价、降级时间、备注和质检图片；记录所属日期与实际降级时刻可以跨日。原成交页的合计与降级后单价分处不同入口，不能未经合同确认就回写原订单金额、扣实物库存或创建新销售决定。

异常列表有“已经到底了～”，不代表成交明细也有同样标志。扫码记录中的序号、货位、数量、打印动作属于履约证据；NFC 入位、扫码、交货、成交、结算各自不是另一类事实的完成证明。

## 其他渠道与规则

- 平台代卖说明显示提交时间 12:00–18:30、结算时间“24小时”，要求送货前核对品种数量、次日上午9点以前核实待交易数量。此为本轮页面说明，不作为已验证 SLA 或自动结算能力。
- 代配规则长图显示平时20:30前交货、节日21:00前交货，按扎收费，扫码入位前的数量/质量责任及迟到、退出规则；这与首页17:55停止结单是不同业务时间，不能合并为一个截止时间。
- 行情页横幅说明每天17:30根据当日实际交易生成；自营与代卖当前默认展示日期不同。因此行情必须携带渠道及所选日期，不默认为实时价格。最高/最低/均价只是该页面行情字段。
- 收益是明确的权限失败；新增商品是商品库不可用；开票是认证前置限制。三者不能统一伪装成空数据，也不自动请求扩大权限。
- 优惠券表单以“满多少扎减”为门槛；目前未证明优惠如何进入成交合计。不能仅按数量×供货价计算真实成交收入。

## UI 自动化可行性与 HTTP API 边界

### 已证实的 UI 行为

- Windows 能单独定位“锦成入驻商家”窗口，与其他供应商小程序区分；多数文本和输入框可被 accessibility 读取。
- 大列表出现 `child_limit` 截断；整页 `document_text` 有时能提供更多行，但也包含隐藏模板和后台保留的上一页面。输入框聚焦时，`document_text` 甚至只返回查询词，不能把它当恒定结构的全页数据源。
- 部分页面返回后/异步加载后元素索引变化；本轮一次返回点击因索引失效被工具拒绝，刷新后用新索引正常返回。索引不能持久化为 selector。
- 普通输入能完成中文查询；一次 accessibility `set_value` 清空未反映到可见输入框，随后通过确认焦点、全选、退格、Enter 成功恢复。工具返回成功不等于页面状态已经改变。
- 列表长滚动需要观察实际进展；一次很大的滚动量并未直接抵达末尾，End 键也没有让列表跳到底。
- 商品列表终点、异常列表终点、订单明细无终点、NFC/售后/统计空态以及收益权限错误需分别处理。

建议把窗口/导航/可见区域/行定位/输入校验留在锦成专属 Reader/Executor，业务层继续消费标准事实。这里的定位是 Adapter 实现细节，不新增公共 page identity proof。

### 尚未获得的 HTTP 信息

`servicewechat.com/.../page-frame.html` 只是微信容器，不是业务 HTTP API。本轮未获得业务域名、method/path、请求/响应 schema、稳定商品/订单 ID、鉴权续期、分页 cursor、错误码、限流、写请求幂等键或条件更新能力，也未获得服务商正式开放接口文档。

因此交付的是**现场页面接口勘察及 Adapter 接入边界**，不是逆向 HTTP SDK。没有读取凭据、解包客户端、注入调试器、改代理/证书、绕过权限、扫描猜测接口或重放请求。未来若取得正式文档或受控业务请求样本，应只记录去除 token/用户资料后的 schema；供应商支持渠道由负责人决定是否联系。

## 与现有 PRA 能力的复用及缺口

**具体设计边界缺口：**现有蚂蚁订单 Adapter 的非空 ACCEPTED 要求 `scroll_completed && no_more_marker_visible`；锦成已查看的单品成交明细没有可见 no-more 标志。直接把“滚不动”或“有汇总”填成 `no_more_marker_visible=true` 会伪造证据，可能把漏单当完整销售事实。

最小处理是先保留 PARTIAL / UNAVAILABLE，不改现有安全门禁；后续寻找可证明完整性的真实来源。若只能使用“所有单品逐页读取、行数/数量/金额对账、确认无加载与明确遍历终点”的替代证据，须先用非生产样本证明其充分性，并明确调整公共完成合同的必要范围。不能在此次探索中偷偷放宽成“有数字就成功”。

本轮没有新增表、持久字段、Service、Queue、状态机、账号体系或生产 Parser。现有能力的主要缺口在平台 Reader、页面字段语义和完成证据，尚无需要扩建基础设施的具体事故证据。
