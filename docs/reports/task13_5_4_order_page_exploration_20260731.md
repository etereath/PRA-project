## 1. 后续权威裁决

首轮探索之后，GitHub Issue #20 正文和评论 `5136623832` 已冻结最终口径。以下结论

  supports_historical_trade_day` 均为 `true`；
- 当前交易日是截至 `observed_at` 的 `OPEN` 快照，历史交易日是 `CLOSED`；
- 页面数量映射为 `order_qty`；
- 页面“合计”映射为 `order_transaction_amount`，汇总名为
  `transaction_amount_total`；
- 成交金额不代表卖家实收、扣佣收入、退款净额或财务到账；
- 当前范围不使用 `effective_qty / refund_qty / invalid_qty /
  seller_received_amount`；
- 取消留到 13.5-5 通过相邻完整快照的多重集合减少推导，不在订单表伪造取消行。

本文只记录已经观察到的页面能力，不声称平台内部修复了任何错误。

## 3. 已验证页面能力

当前日期可以选择并返回四项零值汇总、“暂无订单”和零订单卡片。该结果证明当前日期
可读，但不证明交易日已经关闭；其事实终态只能是 `OPEN`。

两个相邻历史日期可以返回日期汇总、多张订单卡片、精确到秒的下单时间和列表尾部
“没有更多了”。切换离开后再次进入同一历史日期，样本内卡片顺序保持一致。该观察只
证明页面当前能力，不保证未来版本永远使用相同 DOM。

页面结构为：

```text
订单管理入口
→ 日期选择
→ 日期汇总
→ 单列订单卡片
→ 纵向滚动加载
→ “没有更多了”或“暂无订单”
```

完整有数据页必须同时满足：选择日期精确匹配、页面加载完成、全部卡片字段可关联解析、
滚动完成并看见“没有更多了”。空页必须明确看见“暂无订单”。索引读取失败不能替代
结束标记。

## 4. 字段和选择器事实

本轮确认可安全进入只读结果的页面字段：

| 页面字段 | 结果字段 | 格式 |
| --- | --- | --- |
| 订单日期 | `platform_trade_date` | `YYYY-MM-DD` |
| 等级 | `grade` | 文本 |
| 品种 | `platform_product_name` | 文本 |
| 数量 | `order_qty` | 正整数，页面单位为“扎” |
| 合计 | `order_transaction_amount` | 非负十进制金额 |
| 下单时间 | `order_created_at` | `YYYY-MM-DD HH:MM:SS` |
| 单项读取时间 | `observed_at` | 带时区时间 |

已捕获首张卡片字段的末端索引为：

```text
grade = 2
platform_product_name = 3
order_qty = 5
unit_price = 6
order_created_at = 7
order_transaction_amount = 8
candidate_row_stride = 9
```

正式实现不采集单价，`unit_price=6` 仅作为元素结构证据；成交金额通过卡片“合计”
位置读取。后续卡片按候选步长 `9` 定位，并逐卡片验证品种、等级、数量、成交金额和
下单时间。运行时若日期、字段关系或尾部标记不成立，返回 `PARTIAL` 或 `FAILED`，
不得错位拼接。

## 5. 重复订单和取消边界

平台订单号禁止采集，因此身份只能由平台、交易日、下单时间、品种和等级规范化生成。
真实重复订单可能拥有相同指纹，必须用 `occurrence_no` 全部保留，不能去重。

单次页面探索没有能力证明订单取消。13.5-4 只保存不可变快照和可跨快照比较的订单
身份；取消由 13.5-5 在同平台、同交易日、相邻完整快照且非 18:00 换日的前提下，
根据多重集合数量减少计算。

## 6. 探索结论

探索证据足以支持平台 Adapter 的只读实现：

- 当前和历史交易日均可选择；
- 当前日与历史日必须分别标记 `OPEN / CLOSED`；
- 有数据页和可信空页具有不同的完整性证据；
- 日期、滚动、尾部标记和逐项 `observed_at` 必须进入验收；
- 平台订单号和买家 PII 不需要、也不得进入身份合同；
- 候选步长 `9` 只能作为平台 Adapter 的结构常量，不能代替运行时完整性校验。
