## 1. 环境准备

- Python：建议使用 `3.11`
- 依赖安装：

```bash
pip install -e .
```

## 2. 常用启动方式

生成样例工作簿：

```bash
python scripts/create_sample_workbooks.py
```

启动新运营 Web。推荐先在不提交 Git 的 `scripts/local_env.ps1` 中配置固定依赖，再使用
只管理 Web 生命周期的启动脚本：

```powershell
pwsh -NoLogo -NoProfile -File scripts/start_local.ps1
```

直接启动时必须先显式配置 `PRA_ENV`、公开协议和 Cookie 模式；本地 HTTP 使用
`development + http + non-Secure Cookie`。生产必须使用 `production + https + Secure
Cookie`，配置冲突会在启动时给出中文错误并退出。完整变量见
[runtime_environment_variables.md](runtime_environment_variables.md)。

任务预览：

```bash
python -m app.cli preview-tasks ^
  --products data/samples/products.xlsx ^
  --price-rules data/samples/price_rules.xlsx ^
  --listing-rules data/samples/listing_rules.xlsx ^
  --use-mock-ai
```

旧 Excel 任务生成仅保留为隔离测试：

```bash
python -m app.cli generate-tasks ^
  --products data/samples/products.xlsx ^
  --price-rules data/samples/price_rules.xlsx ^
  --listing-rules data/samples/listing_rules.xlsx ^
  --output data/samples/generated_tasks.xlsx ^
  --use-mock-ai ^
  --test-only
```

模拟执行并写回日志：

```bash
python -m app.cli simulate-execution ^
  --tasks data/samples/generated_tasks.xlsx ^
  --logs-output data/samples/execution_logs.xlsx ^
  --updated-tasks-output data/samples/executed_tasks.xlsx
```

## 3. 新运营 Web 推荐流程

1. 进入“业务管理 → 创建任务”，按品种、等级和平台选择范围；
2. 选择“调整价格到、加/降价、下架、上架”并填写该动作所需字段；
3. 先预览并核对逐项阻断、最低成本、映射、价格新鲜度和真实库存；
4. 创建 Runtime Task；该步骤不投递 Queue，也不触碰平台；
5. 在独立的“执行授权”区选择明确 Task，重新准备并核对批次摘要后再提交执行。

创建任务与真实平台执行授权始终是两个阶段。普通 `PENDING` Task 不会因创建成功而自动
执行；日常复核使用 Web/Mobile Review，日常定时业务由 Automation Service 运行。
6. 如需闭环演示，进入 `执行回写` 页面模拟执行

## 4. 常见问题

### 4.1 `invalid headers`

含义：
当前加载的 Excel 首行字段名和系统预期不一致。

排查方式：

- 确认 `products.xlsx`、`price_rules.xlsx`、`listing_rules.xlsx` 没有混用
- 确认 Excel 第一行仍是英文表头，不要改成中文
- Web 页面切换表格类型后，确认路径也跟着切到了对应文件

### 4.2 保存表格时报字段错误

含义：
表格里存在单元格级别问题，例如：

- 必填项为空
- 数字列填了文本
- 布尔列不是 `true/false`
- `internal_sku` 重复

处理方式：

- 看页面顶部错误列表
- 看对应红色高亮单元格
- 修改后重新保存

### 4.3 同一个 SKU 出现多条任务

这在当前设计里可能是正常的。

判断标准：

- 同一 SKU + 不同动作：正常
- 同一 SKU + 同一动作 + 同一平台重复：异常

例如同一商品同时需要 `set_online` 和 `update_price`，会生成两条任务。

### 4.4 `start_web.bat` 启动异常

如果出现乱码或命令被拆断，优先确认：

- 使用的是仓库根目录下最新的 `start_web.bat`
- 没有自己另存为带 BOM 的异常编码版本
- Python 已加入环境变量

可先运行：

```bat
start_web.bat --check
```

### 4.5 浏览器能打开但页面没有数据

通常是样例工作簿还没生成，或路径被改错。

先执行：

```bash
python scripts/create_sample_workbooks.py
```

再检查页面中的默认路径是否存在。

### 4.6 影刀 `test2` 运行浮窗不可捕获或主窗口不可用

`test2` 从影刀“应用”列表启动后，会显示独立置顶的运行浮窗。该浮窗的
进程名通常为 `RobotRunnerView`，不属于 Codex 窗口，也不能只在 Codex 的
窗口范围内查找。运行前优先确认待执行请求；没有请求文件时，流程默认采用
`READ_ONLY`，不要把未知请求直接当作无副作用任务运行。

正常运行与检查顺序：

1. 保持在影刀“应用”主页面，确认目标行名确为 `test2`，从应用列表启动；不要为了运行而打开编辑器。
2. 通过全桌面窗口枚举或 `RobotRunnerView` 的窗口句柄尝试定位运行浮窗；不要根据固定屏幕坐标盲点点击。
3. 若浮窗可定位，读取其状态或结果；流程结束后仍要检查并关闭残留浮窗。

若影刀主窗口在应用运行期间不可捕获，按以下恢复顺序处理：

1. 枚举当前可操作窗口，切换到最近可用的任意窗口。
2. 发送全局快捷键 `Ctrl+Alt+Q`，停止影刀正在运行的应用；此快捷键不依赖影刀主窗口获得焦点。
3. 再次枚举窗口和进程，确认 `RobotRunnerView` 已退出或不再持有运行状态。
4. 若影刀主窗口仍不可定位，结束 `ShadowBot.Shell.exe` 主进程并重新启动影刀。强制结束前应确认没有需要保留的编辑内容。
5. 仅当新的“影刀”主窗口可定位后，才允许继续下一轮 `test2` 运行或外部 Python 同步。

不要把“结果文件已写出”“Worker 已停止”或“任务已取消”视作浮窗一定关闭的证据；每次成功、失败、超时或停止后都要执行上述窗口检查。
