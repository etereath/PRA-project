## 3. 页面状态映射

| 小程序页面 | 位置事实 | `online_status` 投影 | 自动化处置 |
|---|---|---|---|
| 仅在“上架中”唯一出现 | `online_only` | `online` | 无其他阻断时可执行 |
| 仅在“待上架”唯一出现 | `waiting_only` | `offline` | 无其他阻断时可执行 |
| 同时出现在两页 | `both` | `online` | 创建 Review，禁止自动写入 |
| 完整扫描后两页均不存在 | `neither` | `offline` | 创建 Review，禁止自动写入 |
| 身份重复或映射冲突 | `ambiguous` | 保留原值 | 创建 Review，禁止自动写入 |

`SYNC_STATUS` 只需要完整扫描“上架中”和“待上架”。“审核中”和“未通过”不再作为独立平台状态；目标不在前述两页或身份无法确定时进入人工介入。

## 5. 行索引结构

2026-07-25 后续实机复核修正：两页步长不同。

```text
上架中 row_base = 1 + 16 × (row_number - 1)
待上架 row_base = 1 + 15 × (row_number - 1)
```

### 5.1 上架中

| 字段或入口 | 索引规则 |
|---|---|
| 商品容器、名称、等级 | `row_base` |
| 名称 | 商品容器下 `StaticText index=1` |
| 等级 | 商品容器下 `StaticText index=0` |
| 库存 | `row_base + 6` |
| 价格 | `row_base + 9` |
| 编辑按钮 | `row_base + 12` |
| 下架按钮 | `row_base + 14` |

第一行下架按钮实机捕获为 `wx-view index=15`，与 `row_base=1` 对应，确认偏移为 `+14`。

### 5.2 待上架

待上架商品行步长为 `15`，不能复用上架中的 `16`。

| 字段或入口 | 索引规则 |
|---|---|
| 商品容器、名称、等级 | `row_base` |
| 名称 | 商品容器下 `StaticText index=1` |
| 等级 | 商品容器下 `StaticText index=0` |
| 库存 | `row_base + 6` |
| 价格 | `row_base + 8` |
| 上架按钮 | `row_base + 13` |

待上架价格偏移是 `+8`，与上架中现有价格偏移 `+9` 不同。任务13必须建立页面专属行结构，不能直接复用任务12的上架中价格选择器。

行号只用于一次完整扫描内的执行排序和重新定位，不得持久化为商品业务身份。

## 7. 上架和下架确认窗口

### 7.1 上架

点击待上架商品的“上架”按钮只会打开确认窗口，不会立即改变状态。

观察到的提示：

```text
您确定上架【A级 艾莎（10枝）】吗？
```

窗口包含“取消”和“确认”。商品身份出现在提示文本中，执行时必须读取并核对动态身份，不能把捕获时的业务值写死。

### 7.2 下架

点击上架中商品的“下架”按钮只会打开确认窗口，不会立即改变状态。

观察到的提示：

```text
您确定下架【E级 卡布奇诺】吗？
```

窗口包含“取消”和“确认”。同样必须在最终确认前核对动态商品身份。

### 7.3 写操作边界

正式实现应冻结为：

```text
点击上架/下架入口
→ 读取确认窗口动态身份
→ 与当前 operation 的目标身份比较
→ 写 ACTION_INTENT_RECORDED phase
→ 点击最终“确认”
→ 写 ACTION_CLICKED phase
```

入口按钮不是最终副作用边界；确认窗口的“确认”才是上下架状态写入边界。

## 8. 页面扫描结束判定

推荐结束规则：

1. 从 `row_base=1` 开始，以 16 为步长枚举；
2. 读取当前已加载商品；
3. 下一个索引不存在且页面出现“没有更多了”时立即结束；
4. 若下一个索引不存在但页面显示“加载中...”或没有结束标记，则滚动并等待；
5. 等待加载完成后继续枚举；
6. 未验证结束标记时不得把扫描标记为完整。

不再采用固定滚动次数或“三次相同指纹”作为正常结束条件。

### 9.2 SET_ONLINE

额外需要：

```text

```

正式流程在首次写入前完成两页预扫描、身份唯一性检查和全批次门禁。`waiting_only` 项按页面顺序先修改价格和库存、统一回读，再依次上架；`online_only` 且价格库存已经符合目标时可返回 `ALREADY_APPLIED`。

### 9.3 SET_OFFLINE

不需要目标价格或目标库存，但结果必须保存：

```text
pre_offline_price
```

成功判定只要求完整扫描后目标不再存在于“上架中”。该结果可以投影 `online_status=offline`，但旧 `listing_location` 必须失效，等待下一次完整两页 `SYNC_STATUS` 产生新的位置事实。

### 9.4 SYNC_STATUS

## 10. 风险清单

1. 当前页面已经存在真实重复身份，必须在首次写入前整批阻断。
2. 上架中与待上架的价格偏移不同，错误复用会读取或点击相邻控件。
3. 待上架页面存在延迟加载，短暂的索引不存在不能等同于页面结束。
4. 页面存在“属性存在异常”“视频有效期”等附加文本，不能用整页文本位置代替结构化字段。
5. `page-101` 等动态页面 ID 不应成为强约束。
6. 确认窗口捕获时包含具体商品文案；运行时必须读取提示文本并校验动态身份。
7. 任何最终确认点击后，如果回读失败，必须进入 `NEEDS_RECONCILIATION / UNKNOWN`，不能自动重试写操作。
8. 人工探索截图当前保存在影刀应用目录，尚未形成可提交的脱敏 Worker 证据包。
