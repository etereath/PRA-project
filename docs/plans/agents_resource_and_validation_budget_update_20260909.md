# 项目 AGENTS 资源与验证预算更新草稿

状态：已按负责人指示纳入根 `AGENTS.md`；本文件保留形成原因、约束范围与后续复查依据。

## 目标

限制与实际交付无关的文档读取、工具输出、全仓审计、重复测试和过度验收，把开发资源集中在业务实现及其直接风险证明上，同时保留安全、事务、授权和真实副作用门禁。

## 已观察到的浪费模式

- 小改动、文档修改和历史分支推送被扩大为上千项完整 pytest。
- 局部代码检查被扩大为全仓 Ruff，产生大量与当前改动无关的历史输出。
- 全量运行发现旧问题后继续诊断并多次重复运行，偏离原交付目标。
- 多次完整读取旧 `AGENTS.md`、状态页、大型 diff 或 PR 历史，而内容没有变化。
- 简单停止 Worker 被扩展为完整生命周期、窗口和解释器验收。
- 同一 PR 按单条评论反复往返，没有按冻结问题一次汇总整改。
- 为相同语义增加重复 fixture 或测试，用测试数量代替风险覆盖。

## 纳入根规则的裁决

1. 全量回归必须事前向负责人申请并取得明确授权。
2. 定向测试超过 4 个文件、20% 项目测试量或预计 2 分钟时，先申请扩大范围。
3. 文档、状态页、历史快照和单纯推送默认不运行测试或全仓静态检查。
4. 相同 Head 不重复全量；单个失败默认最多重跑一次。
5. 新增测试必须绑定具体生产风险，并先证明现有测试不能覆盖。
6. 规则和大型文档内容未变时不重复读取或回显全文。
7. Git、搜索和测试输出默认摘要化，失败只展开直接相关片段。
8. 明确的小任务采用最小完成证据，不自动升级为完整验收。

## 授权边界

授权推送后由 GitHub 自动运行的必需 CI 可以正常执行；这不授权 Agent 主动重跑 CI。安全门禁测试不得为节省资源而删除，但是否执行完整门禁必须同时服从改动风险和负责人授权。

## 后续复查

后续若再次出现未经授权的完整 pytest、全仓 Ruff、重复大型文档读取、同 Head 多次回归或简单任务扩大化，应视为项目工作流缺陷，先停止扩张并回到本规则规定的最小证据范围。
