## 3. 各平台读取什么

以下为本期路线选择，不把探索中尚未证实的口径升级为平台事实。

| 平台 | 首轮默认销售来源 | 保存内容 | 必须保留的限制 |
|---|---|---|---|
| 寻梦 | X16：首页 → 销售统计 → 今日/明确所选范围 | 页面范围原文、花材名称、等级、销量（扎）、实际终点及采集时间 | 此页未提供逐笔金额；商品卡片“已售”时间跨度未证实，禁止用它冒充今日销量。历史场次可含前晚订单 |
| 锦成 | E08/E09：销售统计 → 所选送货日期 → 自营 | 所选日期、渠道、页头总扎数、花材/等级/规格与数量、采集时间 | 日期是送货日视图；历史查询不能用“今日成交明细”标题判日期。明细覆盖未证实则保留部分状态 |
| 蚂蚁花团 | 复用既有可取得的 UIA 销售累计或订单 Reader，固定本次实际读取的来源 | 已显示的日期/范围、真实累计字段；若为订单，保留行的原始状态和数量 | 订单页可能仍显示旧日。照实标注来源日期，不冒称新交易日累计；不等待冻结窗口才能开始普通记录 |

每个平台先交付一个可用销售来源，不要求扫完整商品库、全部订单历史、售后、行情和结算。
寻梦“普通订单”X11～X13、锦成单品详情 E10 是已知备选：仅当默认销售路径无法完成目标时局部采用，不默认同时建设两套采集器或增加一轮审批。
采用订单来源时须保留订单状态；“全部状态”中的待付款/已取消不能直接相加成有效成交。稳定订单/子行身份不足时保存原始行，不编造订单 ID 或强行去重。
锦成详情没有明确 no-more 标志，不得伪造。已读到的页头汇总和部分行仍可以有用地记录；缺详情完整性不阻止其他平台和已明确范围的数据落盘。

平台名称沿用既有规范；“锦城/锦成”“寻梦/寻梦供应商”在适配边界明确对应，不生成重复公共平台，不增加 account_id/session/page 认证模型。
登录使用现场已登录窗口。无法登录、权限不足或关键树缺失，记录原因并交给现场操作者恢复；不读取凭据、不自动申请权限、不绕过验证码。

## 4. 记录的含义：采样记录，不是经营记账

每份快照至少能回答：哪个平台/页面，读的什么范围，什么时候读，页面给了什么值，覆盖到哪里，有什么限制。
需要的信息分为三组，具体 Python 类型/字段名由实现者在最小范围内确定：

- 采集：本次记录标识、平台、来源页面/类型、开始/结束时间（含时区）、程序版本、成功/部分/失败或跳过原因。
- 范围：页面所选日期或“今日”等原文、渠道/筛选、范围是否确认、实际终点/空态/补载情况。
- 内容：花材、等级、规格（有则保留）、数量与单位、页面直接金额（没有就为空）、页头汇总与逐行数据、必要的字段原文。

“今日”尚无已验证边界时，保留原文与采集时间，不自行生成平台 trade_date。业务现场默认按 Asia/Shanghai 表达采集时间，不继承开发电脑时区。
原始累计22和下一次25是两个时点，不相加成47；默认不把差值3称为精确新增成交。新一轮始终追加，不覆盖上轮记录。
不同平台/日期/渠道/来源/单位不自动汇总成一个“今日总销量”。当前只有分平台记录，不建设 Commitment、Closing、Supply、SKU归属或跨平台分配。
未知数量/金额不补零；读不到、加载中、权限失败与明确空态分别显示。只有绑定范围且加载完成的真实空态才能记为零。
多屏补载须防止重复视口重记；也不能仅按“名称+数量相同”删除两个真实独立行。发生刷新/重复歧义时保留原始行和不完整标记。
页头汇总、逐行合计分别保存，不修改任一值使其强行相等。页面在采集中变化时标注采集区间/差异，不声称跨页原子快照。

不以“本地记录成功”宣称 F1 合格事实、正式成交额或经营 authority。记录不承担任何自动销售、库存扣减或执行授权。

## 5. 最薄实现与定时入口

建议形态：一个单次 CLI、三个平台专属只读 Reader、少量共用 UIA/文件工具和一个本地输出目录。
可使用 `scripts/run_uia_sales_recorder.py` 作为入口；路径为建议，不强制为此重命名已有可复用模块。
提供单次指定平台/全部平台采集和历史汇总读取；主 PRA Runtime、Web、Queue、Automation Service 不启动也能工作。

定时采用 Windows 任务计划调用单次命令，不新建常驻 daemon、消息 Queue 或调度数据库。首次安装/启用与代码交付分开。
建议初始周期30分钟，平台启用项、周期/时段、查询范围、输出目录、单次超时可配置；30分钟是规划建议，不是平台规则或已获现场启用授权。
同一轮按启用平台串行。上一轮未结束不启动第二轮、不积压补跑；错过的采样保留缺口，不伪造历史。
先提供一个适合“用户已登录、桌面可用”的任务模板及启用/暂停/卸载说明；不开发开机自动登录、自动解锁或后台无桌面执行。

文件建议：`<output>/runs/<platform>/<日期>/<唯一记录>.json`。
先写临时文件，完整序列化后原子发布；未完成文件不计成功。已发布历史不覆盖；崩溃后可重扫当前页面，不需要恢复旧 UI 导航到一半的位置。
提供从快照生成的 UTF-8-SIG CSV 汇总，列出来源范围、数量/金额、完整性、最近采集结果及路径。JSON 是唯一记录，CSV 可重建，不再维护第二个权威台账。
最新失败不得把历史成功记录改成零或伪装为刚更新；汇总同时显示最近尝试及最近成功时间。过期数据不是当前成功。
输出放在独立本地目录并排除 Git。只留销售必需字段，不采客户联系方式、地址、凭据；PR样本须脱敏。默认不每轮保存全屏截图，排错只保存必要局部证据。
不使用 PRA 生产 SQLite 或旧 Order Importer 的 Settlement/Inventory post-import 副作用链；本任务不需要新数据库、表、迁移、Service 或通用 Provider 框架。

## 6. UIA 与同桌面安全：采用运行约束，避免扩建主系统

只允许已确认的导航、日期/查询筛选、滚动、读取和无提交返回。
不进入商品编辑、价格/库存面板、批量操作、履约确认、打印、结算、提现或发消息；不提供自由脚本/任意按钮执行接口。仅设置 READ_ONLY 标志但仍调用写 Executor 不算隔离。
选择器属于平台 Reader；每次导航重新定位当前控件，不持久化探索会话索引。隐藏模板、上一页面、输入框内查询词不能当活动销售结果。
焦点被人工切走时停止当前扫描，不反复抢焦点；不结束微信或其他用户进程。

首版受支持运行方式是：专用交互桌面，或负责人已明确停止其他 UI 自动化后的受控窗口。开发环境复用同桌面时先协调场地，不修改 F1/F2 的任务或生产锁。
同桌面三平台和本扫描器多个入口使用一个本地 OS 互斥/等效已有机制；它只防本工具重入，不宣称与未接同一互斥的 ShadowBot/主服务已经安全共存。
本 PR 不为了共存重写主 Worker/Queue。仅当前 Queue 为空、时间错峰、旧心跳不见了，都不足以证明无人操作桌面。

若使用 UIA 子进程，复用已存在的有界进程方案；持锁范围必须覆盖最后一个仍可能导航的自有进程。
超时后先停止并确认自有子进程退出，再进入下一平台。父进程退出也不能留下子进程在后台继续点击；相关边界做直接进程测试。
单平台读取失败：记录失败 → 释放该次已停止的扫描 → 扫下一平台 → 下个定时周期重试。不建持久重试队列或人工 Review 工作流。
若无法确认残留导航已停止，或桌面整体不可用，结束本轮并报告原因；这不是 PRA 全局业务 blocker，不改主系统锁，也不猜测关闭 UNKNOWN。
需要恢复时，现场操作者重新登录/恢复桌面；下一次单次命令或定时触发重新读取，无需修数据库、认领或补齐审计链。

## 9. 后续接入与 S3：不能让临时旁路永久膨胀

本任务输出仅是独立销售采样，不作为 F1/F2 验收替代，也不宣告 F3/S3 完成。
后续接入主服务时复用相同 Reader 和解析逻辑，通过适配消费本地采样格式或直接调用，不重新实现同一平台 Reader。
某平台相同范围的主服务采集接管并完成验证后，由接入任务负责人停用该平台独立定时项、删除被替代的CLI包装/重复配置和无人消费的兼容代码；历史快照保留。
过渡期可以分平台接管，但同桌面不能出现未隔离的两套调度。独立文件不是主服务失败后的隐式权威 fallback。
若某独立入口继续有真实人工导出用途，记录消费者和理由；“未来可能用到”不能作为保留第二经营链的依据。有关减法随相应接入任务交付，不把清理留成无负责人待办。
