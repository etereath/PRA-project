![None](https://xybot-oss-cdn.yingdao.com/yddoc/rpa_zh-CN/asset/710449654302978048/5106df9d-f036-4227-a04b-79bd5e6004e4/img17.png)


#### 解决方案：

通过 JavaScript 获取图片链接。

**方法一**


![None](https://xybot-oss-cdn.yingdao.com/yddoc/rpa_zh-CN/asset/710449654302978048/124fe7d8-1fa2-425b-ad9f-14e67e4e1513/img18.png)


```None
function (element, input) {
    var url = getComputedStyle(element, null)['background-image'];
    return url.substr(5, url.length-7)
}
```

**方法二**


![None](https://xybot-oss-cdn.yingdao.com/yddoc/rpa_zh-CN/asset/710449654302978048/26fd3792-5c13-4f87-89a5-1553ab0d80e4/img19.png)


```None
function (element, input) {
style = element.currentStyle || window.getComputedStyle(element, false);


bi = style.backgroundImage.slice(5, -2);


return bi;
}
```

- 操作目标：选择图片元素

## 问题引出

懒加载问题是指网页只渲染页面上显示的元素，在屏幕外面的元素无法校验到或获取到信息。下面以聚水潭订单信息获取为例。


![None](https://xybot-oss-cdn.yingdao.com/yddoc/rpa_zh-CN/asset/710446580844957696/8124c644-7462-47bd-b68e-1098e05df4e5/img0.png)

一页上有 50 个订单信息，但是网页代码中只有 16 个元素被加载出来，如果继续滚动网页：


![None](https://xybot-oss-cdn.yingdao.com/yddoc/rpa_zh-CN/asset/710446580844957696/edabdd85-95c1-4aea-bd58-562c21fcb11d/img1.png)

后面的元素会被加载出来，但是前面的元素会消失。总是有元素不显示，影响数据的获取。


## 解决思路

在循环中维护一个列表，记录已经抓取过的行数据，无限循环向下滚动鼠标滚轮并获取当前可见的元素，用这个 index 属性和列表对比判断，如果这个元素的数据已经抓取，跳过。如果已经抓取到的数据数量已经达到 50 条，则停止抓取数据。

如何判断一条数据是否已经被抓取过了呢？

发现网页代码中，数据行元素的 index 属性是唯一确定的，是从 0 到 49 的 50 个数字。验证一下想法：


![None](https://xybot-oss-cdn.yingdao.com/yddoc/rpa_zh-CN/asset/710446580844957696/448f5eec-9fb3-4520-8e4c-400f09756542/img2.png)

打印出了当前页面上显示的 6-17 行。

试一下用这种思路是不是能打印出这一页上所有行元素的 index 值。


![None](https://xybot-oss-cdn.yingdao.com/yddoc/rpa_zh-CN/asset/710446580844957696/bda0cf0b-7412-42ad-b30b-3c87f52ae222/img3.png)

**流程执行逻辑：**

获取已打开的聚水潭订单网页对象 -> 新建列表`记录列表`用于记录获取过的行的 index 属性 -> 开始无限循环向下滚动，无限循环的退出条件是，记录列表的长度是 50（已经抓取到页面上所有的行元素属性数据）-> 在无限循环中开始循环相似元素，循环获取当前网页上的所有行元素的 index 属性，如果这个属性已经在`记录列表`里，继续下一次循环，按相同规则判断页面上下一个行元素；如果这个属性没有在`记录列表`中，则打印这个属性，并添加这个属性到列表中 -> 每进行完一次循环当前页面上显示的相似元素，鼠标在网页上向下滚动，并判依据上述条件判断是否到底，如果到底退出整个循环

### 找不到类似 index 的属性

有些网站的行元素可能不会有像 index 一样可以唯一确定的属性来判断，这种情况考虑用页面上原有的数据作为唯一判断标准，比如订单号，商品编码等。

下面以聚水潭的内部订单号替代 index 作为判断标准在同一界面进行数据抓取。


![None](https://xybot-oss-cdn.yingdao.com/yddoc/rpa_zh-CN/asset/710446580844957696/13e497b2-c97d-4867-9195-f0d0fa7cdfac/img9.png)

**流程执行逻辑**类似，唯一不同的地方是不再获取行元素的 index 而是关联了当前循环到的行元素为父元素去找内部订单号作为判断标准，记录在记录列表中作为判断依据。


### 不确定当前页面上共有多少数据

有时候不知道当前页面有多少行数据，无法根据记录列表的长度判断无限循环是否需要退出（页面已经到底），这个时候需要考虑其他判断条件。

注意到如果不做判断，无限循环一直进行下去，但即使已经滚动到屏幕底部，`记录列表`和`数据列表`的长度都不会再变化了，因为我们已经做了判断，记录列表里已经有过记录的数据不会再抓取。所以可以据此判断页面是否已经到底。

在循环中记录上一次`记录列表`的长度，在循环完当前页相似元素后的`记录列表`的长度对比，如果没有增加，就退出外层无限循环。

### 网页有刷新行为

### 元素编辑中，如何限定属性不包含某一段字符串？

如果有某个复选框元素的的勾选与否取决于其某一个属性，勾选时属性为 `CBX_active_18l33c8`，不勾选时属性为 `CBX_18l33c8`，如何判断这个复选框是否已经勾选？

- **方案一**：捕捉并编辑元素时不勾选这个属性，使得在勾选和不勾选是都可以校验到元素，用获取元素属性指令获取这个属性的文本，用内置的 If 指令判断是否包含 `active`。
- **方案二**：影刀的元素编辑中所有属性都支持通配符和正则表达式，正则表达式可匹配（不）包含某个子字符串的字符串，语法如下：`^((?!active).)*$`，意思是匹配所有不包含 `active` 的字符串。如果要同时排除多个关键字，语法为 `^((?!disabled|prev|diff).)*$`，意思是匹配所有同时不包含 `disabled`、`prev `和 `diff` 的字符串，即在该属性中不能包含三个中任意一个。

由于平台自身设计漏洞导致订单数据部分缺失。



### 订单导出流程


![None](https://xybot-oss-cdn.yingdao.com/yddoc/rpa_zh-CN/asset/710408776380825600/3a760db4-0be4-48fb-810b-4de3c78f6beb/img0.png)


### 思路重点：

1.由于订单是按照时间倒序排序，即第一页的订单来自于当天最晚的时刻，且已知一页订单数为固定数量15个，因此选择每次循环导出600页（即600*15=9000条）订单数据。选择空出1000条数据空间是为了防止大促的时候平台每秒钟订单量激增使前600页数据加起来超过10000条，进而导致导出数据失败，流程无法成功运行。


![None](https://xybot-oss-cdn.yingdao.com/yddoc/rpa_zh-CN/asset/710408776380825600/64ef97a0-be61-4e6a-a74c-ad215e012203/img1.png)

2.获取最大页数后判断是否大于650页。

- 若总页数<650，则将所有订单数据全部导出
- 若总页数>650，则跳转至第600页，获取第600页最后一个订单的下单时间作为查询时间的起始时间，结束时间设为当天的23：59：59。（第一个循环的时间段）

若总页数<650，则将所有订单数据全部导出

若总页数>650，则跳转至第600页，获取第600页最后一个订单的下单时间作为查询时间的起始时间，结束时间设为当天的23：59：59。（第一个循环的时间段）



![None](https://xybot-oss-cdn.yingdao.com/yddoc/rpa_zh-CN/asset/710408776380825600/4bf3e565-6f4b-4df9-93c0-33eaaf658cdb/img2.png)


![None](https://xybot-oss-cdn.yingdao.com/yddoc/rpa_zh-CN/asset/710408776380825600/d175f981-3f8f-4274-8965-d25018842aad/img3.png)

这样就能找到区间范围（9000，10000）的订单数量所对应时间段范围了。每600页取一次查询起始时间，再将上一次循环的起始时间作为下一次循环的结束时间。每次循环前判断剩余页数是否小于650,若小于则导出最后一次数据后退出循环。


### 数据查漏和去重

由于平台自身漏洞会导致导出订单的时候部分数据缺失的情况，为了保证数据的完整性和准确性可以每天运行>2次导出订单的应用（次数越多越接近真实订单数据，但不建议运行太多次），再将每次导出的数据进行去重，保留最后完整的数据即可。

- CentOS 7

- CentOS 9 (stream)

CentOS 8 (stream)

CentOS 9 (stream)

必须启用centos extra存储库。默认情况下会启用此存储库，但如果已禁用它，则需要重新启用它。

旧版本的Docker被称为Docker或Docker引擎。在尝试安装新版本以及相关的依赖项之前，请先卸载任何此类旧版本。

(新服务器未安装过忽略)


```None
sudo yum remove docker \
                  docker-client \
                  docker-client-latest \
                  docker-common \
                  docker-latest \
                  docker-latest-logrotate \
                  docker-logrotate \
                  docker-engine
```


### 设置储存库

安装“yum-utils”包（它提供了“yum-config-manager”实用程序）并设置存储库。


```None
yum install -y yum-utils
```


```None
yum-config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo
```


### 安装 Docker Engine, containerd, and Docker Compose:


```None
yum install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

启动 Docker 并设置开机自启


```None
sudo systemctl start docker
```


```None
sudo systemctl enable docker
```

### 卸载旧版本(新服务器忽略)

运行以下命令以卸载所有冲突的包：


```None
for pkg in docker.io docker-doc docker-compose podman-docker containerd runc; do sudo apt-get remove $pkg; done
```

更新apt包索引并安装包，以允许apt通过`HTTPS`使用存储库：


```None
sudo apt-get update
sudo apt-get install ca-certificates curl gnupg
```


### 设置储存库


```None
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg
```


```None
echo \
  "deb [arch="$(dpkg --print-architecture)" signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
  "$(. /etc/os-release && echo "$VERSION_CODENAME")" stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
```


### 安装 Docker Engine


```None
sudo apt-get install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

验证 Docker 引擎安装是否成功 `hello-world`。


```None
sudo docker run hello-world
```

#### 导出应用的作用

当任务包含大量应用，且这个任务的复用率较高时，可以使用导出应用功能，将任务中包含哪些应用以及应用的执行顺序导出为excel文件，文件形式如下：


![None](https://xybot-oss-cdn.yingdao.com/yddoc/rpa_zh-CN/asset/710399793949257728/99be61fe-f5b4-4f98-a855-4414a7b2093e/img0.png)


#### 新建/编辑任务时导入应用的注意事项

1. 上传成功后，我们会按照excel文件中自上而下的顺序，排列任务执行应用的顺序。
2. 如果excel文件中单行数据读取失败，则应用全部上传失败，需调整好exce文件后，重新上传。
3. 编辑原有的任务时上传excel文件，则会替换掉原有任务中的应用。
4. 应用导出后请勿修改应用uuid，修改uuid会导致导入失败或异常。
5. 如果调整应用执行顺序、删除应用，需对【整行】进行调整、删除。
6. 应用发版后名称进行了修改，那原来excel文件中的名称将和现有的名称有差异。
